# Tâches GSA – démo

👉 **Version en ligne : https://lionelbonati-lab.github.io/Taches_GSA/** (installable sur ordinateur et téléphone)

Application de démonstration pour gérer les tâches du comité du club.

> **« Point » plutôt que « tâche »** dans l'appli : un point peut être une chose à faire ou une simple information (comme un point de l'ordre du jour). Les textes affichés disent « point » (« Mes points », « Nouveau point », « Voir tous les points »…) ; le code, les données, les adresses (`#/taches`) et le nom de l'appli (« Tâches GSA », réglable dans la console admin) gardent l'ancien mot, et cette documentation aussi. Les emails programmés reconnaissent `{point}` et l'ancien `{tâche}`.
**Aucune base de données** : les données sont fictives et les modifications sont gardées uniquement dans le navigateur (localStorage). Le bouton « Réinitialiser la démo » (écran de connexion ou Réglages) recharge les données d'origine.

> **Une appli plus simple** (`PLAN_APPLI_SIMPLE.md`, étapes D1 à D5 faites) : un seul espace, le club ; plus d'entités ni d'organigramme ; des **étiquettes** (événements, groupes) pour regrouper les tâches et les personnes (voir « Un seul espace et les étiquettes »).

## Lancer

```bash
npm install
npm run dev        # http://localhost:5173 (accessible aussi depuis un téléphone du même réseau)
npm run build      # version statique dans dist/ (vérifie aussi les types)
npm run lint       # contrôle automatique du code (ESLint : règles des hooks React, erreurs courantes)
npm test           # tests automatiques de la démo sur la version construite (après npm run build)
```

**Organisation du code.** Un seul espace, le club (`PLAN_APPLI_SIMPLE.md`) : `src/data/store.tsx` est la couche de données des écrans ; autour d'elle : `storeTypes.ts` (ce qu'elle offre), `club.tsx` (les services du club : l'espace, les personnes du club, les propositions, la sauvegarde…), `migrate.ts` (mise à niveau des anciennes données), `suivante.ts` (occurrence suivante d'une tâche récurrente), `pileAnnulation.ts` (Annuler / Refaire). Démo : `DemoApp.tsx` et `data/demoClub.ts` (données gardées dans le navigateur) ; version réelle : `CloudApp.tsx` et `CloudClub.tsx`. `data/repriseEntites.ts` reprend les anciennes entités en étiquettes (démo d'avant ; mêmes règles que la reprise du serveur, migration 059). La fiche d'une tâche (`src/components/TaskModal.tsx`) s'appuie sur ses parties dans `src/components/tache/` : « Pour quand ? », à prendre, pour info, checklist, répétition, rattachements.

## Rôles et permissions

Tout se règle dans **Console admin › Rôles et droits**, sans toucher au code :

- **Créer un rôle** (vide, copie d'un rôle existant, ou **modèle « Externe »**), le renommer, changer sa couleur, le dupliquer, le supprimer (une fois retiré à tout le monde). Le rôle **Externe** (prestataire, aide ponctuelle…) ne donne que « Créer et modifier ses propres tâches » : la personne ne voit que les tâches qui lui sont attribuées ou qu'elle a créées.
- **Cocher les droits** de chaque rôle : tâches (voir toutes, créer/assigner, modifier toutes, modifier les siennes, supprimer), pages visibles (Séances, Ordre du jour, PV, Événements, Membres du club ; email et téléphone des personnes dans leur fiche), gestion (séances, événements, personnes), administration.
- **Limiter un rôle à certaines sections** : ses droits « Tâches » ne s'appliquent alors qu'à ces sections.
- **Cumuler plusieurs rôles** par personne (« Personnes du club », clic sur son nom › « Dans l’appli ») : chaque rôle apporte ses droits sur ses propres sections.
- Garde-fous : le rôle Admin est verrouillé, chacun garde au moins un rôle, il reste toujours un admin actif.
- **Ce que chacun voit** : ses tâches (responsable, créées par soi), celles des **étiquettes dont il est membre** (migration 062) et, avec « Voir toutes les tâches », celles des sections de son rôle. Sans ce droit (bénévole, responsable d'activité, externe…), seulement les siennes. Les **tickets** (remboursements, factures) ont leur propre règle, séparée : la caisse, le demandeur, la personne à qui le visa est demandé (puis qui l'a visé) et les admins ; « Voir toutes les tâches » ne suffit pas. En version réelle, c'est le **serveur** qui l'applique (il n'envoie rien d'autre, fichiers joints, emails programmés et notifications compris ; le journal : console admin).

## Un seul espace et les étiquettes

Depuis l'étape D1 (`PLAN_APPLI_SIMPLE.md`), l'appli n'a **plus d'entités ni d'organigramme** : un seul espace, le club, avec ses personnes, leurs **rôles du club** (sur leur fiche), ses sections, statuts, tâches, séances et événements. Plus de partage entre entités, de dépendances, de vue « moi », de choix d'entité ni d'« anciennes tâches » ; l'ancienne adresse de l'organigramme mène à « Personnes du club ».

- **Étiquettes** (`{ id, nom, couleur, type: 'evenement' | 'groupe', date?, dateFin?, membres, lieux?, parDefaut? }`) : une tâche porte une ou plusieurs étiquettes (fiche de la tâche, « Étiquettes »). Une étiquette est un **événement** (avec sa date, et un dernier jour s'il dure plusieurs jours) ou un **groupe** (école, compétition…). Ses **membres** voient ses tâches ; **pas de responsable d'étiquette** : les droits restent ceux des rôles du club. Réglées par le bouton **« Étiquettes »** de la page Tâches ou **Console admin › Sections, statuts et étiquettes** (droit « Gérer sections, statuts et étiquettes ») ; les membres aussi depuis la fiche de la personne (« Personnes du club »).
- **Place d'une étiquette et étiquettes d'office** (`src/data/etiquettes.ts`, 03.11.2026) : chaque étiquette a sa **place**, une section (« Gruppetto ») ou une sous-section (« Événements › Week-end VTT ») ; tant qu'elle n'est pas réglée, elle est **devinée d'après le nom** (même nom aux dates près, sinon un nom qui contient tous ses mots : « Compétition » → « Groupe compétition »). Un point rangé à cette place **reçoit l'étiquette d'office** (🔒 dans la fiche : elle ne s'enlève pas à la main) et la perd s'il est rangé ailleurs. L'étiquette **« Comité »** (`parDefaut`, créée par « ＋ Étiquette « Comité » » dans la fenêtre des étiquettes ; ses membres : les personnes qui ont accès aux séances) va aux points rangés **hors de la place des autres étiquettes** ; leur discussion est alors réservée à ses membres (règle 062). Les points d'avant ce réglage reçoivent l'étiquette de leur place quand on les enregistre, ou d'un coup (« Ajouter l'étiquette de leur place »). **Qui range et étiquette quoi** (dans l'appli, comme les droits par section) : à la main, on ne met que les étiquettes **dont on est membre** (toutes avec « Gérer sections, statuts et étiquettes ») ; sans « Voir tous les points » d'une section, un **membre d'étiquettes qui ont leur place** n'y range un point (nouveau ou déplacé) que là où il reçoit l'une d'elles : le camp VTT dans le camp VTT. Sans étiquette placée, les sections de ses rôles, comme avant.
- **Où on les retrouve** : pastilles dans la liste et le kanban, filtre « Étiquette » ; une étiquette **événement datée** apparaît dans l'**agenda** (et son export) et à l'**accueil** (« Prochains événements », avec l'avancement de ses tâches ; un clic montre ses tâches) ; « Pour quand ? » peut caler un délai sur sa date (« 2 jours avant ») : la tâche porte alors l'étiquette, et le délai suit sa date ; « Pour info » et « À prendre » proposent ses membres d'un coup ; un email programmé peut partir à tous ses membres ; la recherche (Ctrl+K) la trouve.
- **Version réelle** : la reprise (migrations 059 et 060, appliquées le 03.11.2026) a fait des entités des étiquettes du club, avec leurs tâches et leurs personnes ; chacun ouvre l'espace du club (les entités, archivées, ne sont plus proposées ; rien n'est effacé). Les fonctions serveur (`gsa-push`, `gsa-agenda`, `gsa-acces`) sont adaptées à l'espace unique (étape D4) et déployées le 03.11.2026 (`SUPABASE_SETUP.md`, « Fonctions serveur »). Ménage (étape D5) : la **migration 061** retire 23 fonctions du serveur que plus rien n'appelle (à appliquer par le président ; `SUPABASE_SETUP.md`).
- **Propositions d'amélioration de l'appli** : menu du compte › **💡 Proposer une amélioration**, pour tout membre du club. On choisit **💡 Idée, 🐞 Problème ou 💬 Autre**, on écrit, et la **page concernée** est déjà choisie (celle d'où l'on vient ; « Toute l'appli » sinon). La proposition est rangée **au club**, avec le nom de l'auteur ; les **admins** sont prévenus (🔔) et la traitent sur la même page, dans « 📥 Propositions reçues » : **statut** (nouvelle, à l'étude, retenue, faite, pas retenue), **réponse** à l'auteur, suppression. L'auteur suit le statut et la réponse dans **« Mes propositions »**. En version réelle : migration 022 (sans elle, la page l'indique et n'envoie rien).
- **⚠ Rapport d'erreurs automatique** : quand une page ne s'affiche pas ou qu'une erreur survient, l'appli la **signale d'elle-même** aux admins (l'écran « Oups » le dit), sans rien demander à la personne. Ils les trouvent dans **Console admin › Erreurs de l'appli** : message, emplacement dans le code (à déplier), page, version, appareil (« Safari · iPhone »), première et dernière fois, **nombre de fois et de personnes** (une même erreur est comptée, pas répétée). Boutons **Réglée / Rouvrir** (une erreur réglée qui revient se rouvre), **Copier** (pour la faire corriger), **Effacer les réglées**, **Envoyer une erreur d'essai** et **Actualiser**. Ni noms ni données des tâches ; chaque erreur part une fois par ouverture de l'appli (10 au plus) ; coupures de réseau, mises à jour de l'appli et extensions du navigateur sont laissées de côté. En version réelle : **migration 051** ; démo : gardé dans ce navigateur.
- **Logo** : le **logo du club**, dans **Console admin › Apparence** (admins). L'image choisie (PNG, JPEG, WebP, GIF ou SVG) est réduite à 256 px avant d'être enregistrée. Il remplace celui de l'appli en haut à gauche, pour tout le monde, et sert d'image par défaut à l'en-tête des documents (ordre du jour, PV, bon de paiement) ; sans logo du club, l'icône de l'appli reste.
- **Couleur de l'appli** (boutons, onglet actif, liens, calendrier…) : même onglet de la console admin, 8 teintes (dont « Vert GSA ») ou « Autre… » (couleur libre). Elle vaut pour tout le club (bleu d'origine par défaut) : la même pour tout le monde. La teinte est ajustée automatiquement pour rester lisible (texte blanc sur les boutons, thème clair et sombre).

## Navigation

Les rubriques sont en haut de l'écran (leur nom sur grand écran ; icône et nom en petit sur écran moyen ; icône seule, nom au survol, sur petit écran) ; une rubrique de plusieurs pages les propose juste en dessous (sous-onglets). Chacun ne voit que les pages permises par ses rôles.

**Barre du bas (téléphone)** : jusqu'à **5 onglets** à côté de « Plus » (d'origine : Accueil, Tâches, Messages, Agenda, Comité), les autres dans « Plus ». **Chacun choisit les siens et leur ordre** : « Plus › Modifier la barre du bas » ou Réglages › Barre du bas (cocher, ↑ ↓ ; « Barre d'origine » revient au départ). Retenu avec ses préférences (`prefs.barreBas`), sur tous ses appareils ; un onglet sans droit est simplement sauté.

**Clavier du téléphone ou de la tablette** : la page se rapetisse au-dessus du clavier au lieu de glisser dessous. L'en-tête et la barre d'outils du PV restent à l'écran, et pendant qu'on écrit, le bouton « + » et la barre du bas laissent la place ; ils reviennent quand le clavier se ferme (Android : réglage `interactive-widget=resizes-content` de `index.html`, repère dans `src/clavier.ts`).

**Icônes** : les rubriques, les pages et les boutons portent des icônes dessinées au trait, de la couleur du texte (bibliothèque [Lucide](https://lucide.dev), licence ISC ; la poubelle est dessinée pour l'appli).

**Cartes** (lieu des séances) : bibliothèque [Leaflet](https://leafletjs.com) (licence BSD-2), chargée seulement à l'ouverture d'une carte ; fond de carte et recherche d'adresses [OpenStreetMap](https://www.openstreetmap.org/copyright) (© les contributeurs d'OpenStreetMap, attribution affichée sur la carte ; recherche Nominatim, seulement au clic sur « Chercher »). Les liens « voir sur la carte » et d'itinéraire ouvrent Google Maps, Waze ou Plans ; seules les coordonnées du lieu y figurent. Les repères (répétition, délai calé, pour info, à prendre, étiquette…) et l'épingle de la carte sont dessinés au trait, comme les boutons ; restent des émojis : les listes déroulantes natives et les états des paiements.

| Rubrique | Pages |
|---|---|
| 🏠 **Accueil** | résumé personnel |
| ✅ **Tâches** | tâches, remboursements et paiements de factures |
| 💬 **Messages** | les discussions des tâches, comme une messagerie (pastille rouge : messages non lus) |
| 📅 **Agenda** | Calendrier · Événements |
| 🗓️ **Comité** | Séances · Ordre du jour · PV |
| 📊 **Sondages** | sondages du club |
| 📇 **Personnes du club** | la liste unique du club, pour tout le monde (coordonnées et gestion selon les droits) |

**↶ Annuler** (en haut, à côté de la cloche ; icône seule sur téléphone) : défait la **dernière action** faite ici (tâche créée, modifiée ou changée de statut, présences et début de séance du PV, PV remis à zéro, réglage de la console admin…) ; plusieurs clics remontent les actions une à une (20 au plus). Aussi **Ctrl+Z** (⌘Z sur Mac) hors d'un champ de saisie : dans un champ, le navigateur annule la frappe, et la frappe des notes du PV ne fait pas partie des actions. Le survol du bouton dit ce qui sera annulé ; l'annulation est notée dans l'historique (« Annulé : … »). Seuls les éléments changés par l'action reviennent comme avant : si l'un a été modifié depuis (autre action, autre membre), les champs touchés depuis sont gardés (« Annulé en partie »). Les actions de la session en cours seulement (rien après un rechargement de la page ou un changement de personne), et pas celles enregistrées aussi ailleurs : paiements (visa, caisse), fichiers joints effacés (tâche supprimée, fichier retiré), « Je m'en charge » / « Pas dispo ». Les emails déjà partis et les fichiers déposés ne sont pas repris. **↷ Refaire** (icône à côté d'« Annuler », dès qu'une action a été annulée) la refait ; aussi **Ctrl+Y** ou **Ctrl+Maj+Z** (⌘⇧Z sur Mac). Une nouvelle action vide la liste de ce qui peut être refait.

**🔍 Rechercher** (la loupe en haut, entre « Annuler » et la cloche ; aussi **Ctrl+K** ou ⌘K, ou **/** hors d'un champ de saisie) : cherche parmi ce que la personne a le droit de voir : **tâches** (titre, remarque, checklist, noms des documents, sous-section), **séances**, **PV et ordres du jour archivés** (tout leur texte), **sondages** (question, description, choix), **événements** (nom, lieu, description), **personnes** (nom, poste ; email et téléphone pour qui voit les coordonnées) , et les **étiquettes**. Sans tenir compte des accents ni des majuscules ; avec plusieurs mots, chacun doit se trouver. Résultats groupés par genre (5 par groupe, « Afficher les N autres »), titre qui commence par la recherche d'abord ; passage trouvé surligné, avec un extrait quand il n'est pas dans le titre. ↑ ↓ et Entrée au clavier, Échap pour fermer ; la dernière recherche reste dans le champ. Un clic ouvre la tâche, la liste des personnes du club (filtrée sur elle), le sondage, le PV archivé, ou amène la séance ou l'événement à l'écran (encadré quelques secondes) ; une étiquette mène à ses tâches. Rien ne part au serveur : la recherche se fait dans l'appli.

**Club** : **Personnes du club** (la liste unique, pour tout le monde ; l'ancienne adresse de l'organigramme y mène).

**Mon compte** (pastille en haut à droite ; « Plus » sur téléphone) : Réglages, **Console admin** (admins) et **Mots de passe oubliés** (admins, s'il y a des demandes), **💡 Proposer une amélioration**, **Comment ça marche ?** et déconnexion. Une **phrase d'explication** sous le titre de chaque page dit à quoi elle sert (masquable dans Réglages) ; **Comment ça marche ?** reprend toutes les pages et les gestes courants (selon les droits de chacun), et l'accueil y invite à la première visite. Les adresses des pages n'ont pas changé (liens déjà envoyés, raccourcis).

- **Accueil** : compteurs de mes tâches par statut (**un clic ouvre la liste filtrée**, « En retard » compris), mes tâches en retard, échéances à venir (7 jours par défaut), emails à envoyer, prochaine séance, **prochains événements** (les trois suivants : ceux de l'agenda et les **étiquettes « événement » datées** ; un événement et une étiquette du même jour, de même nom, ne comptent qu'une fois) avec leur avancement. **Chacun choisit ce qu'il y voit** (bouton « Personnaliser » à côté de « Bonjour », ⚙ seul sur téléphone, ou Réglages › Mon accueil) : chaque bloc et chaque compteur s'affiche ou se masque, **séparément sur téléphone et sur ordinateur**, et **↑ ↓ change leur ordre** (le même sur les deux). Sur ordinateur, les compteurs prennent toute la largeur ; entre eux, les tâches vont à gauche et les autres blocs à droite, dans l'ordre choisi. Le choix est enregistré avec ses préférences et le suit sur tous ses appareils ; Le bloc **« À faire »** se règle aussi : **nombre de jours** (3 à 90, choisi directement dans son titre ou dans « Personnaliser ») et, pour qui voit toutes les tâches, **mes tâches ou toutes**. « Accueil d'origine » remet tout comme avant. Sur téléphone, les compteurs sont compacts (le nombre devant le libellé, trois par ligne). Dans le bloc **👁 Pour info**, **✓ Vu** retire une tâche de l'accueil (« je suis au courant ») ; elle reste dans Tâches (Mes tâches, 👁 Pour info). **L'auteur le voit** : le « Vu » est aussi noté sur la tâche (voir 👁 Pour info plus bas). **Réafficher (n)**, dans le titre du bloc, remet celles marquées « Vu » ; le bloc disparaît quand toutes sont vues. Retenu avec ses préférences (tous ses appareils).
- **Étiquettes** (événement, groupe… ; voir « Un seul espace et les étiquettes ») : une tâche peut porter une ou plusieurs étiquettes, à leur couleur sur la liste et les cartes ; filtre « Étiquette ». Les **membres** d'une étiquette voient ses tâches (« Toutes »), avec qui s'en occupe ; pour les modifier, ce sont les droits de leurs rôles qui comptent (pas de responsable d'étiquette). Bouton « Étiquettes » de la page Tâches (droit « Gérer sections, statuts et étiquettes »).
- **Tâches** : section, sous-section, tâche, responsable(s), statut, délai, remarque, tâche principale / tâches rattachées, sous-tâches ; « Mes tâches / Toutes », filtres, tri, vue tableau ou kanban (glisser-déposer), export CSV, impression. Les statuts sont **les mêmes pour tout le club** (Console admin › Sections, statuts et étiquettes). Les filtres **« Étiquette »** et **« Événement »** ne proposent que les choix qui ont des tâches avec les autres filtres (ils ne se contredisent jamais) ; « Événement » réunit les événements de l'agenda.
  - **🙋 À prendre** : dans le formulaire d'une tâche, « Ajouter : » › **🙋 À prendre** propose la tâche à quelques personnes (« ＋ Proposer à… » : une personne, **tout un rôle**, les membres d'une étiquette ou **tout le monde** ; « Comité » = tout le comité, y compris les personnes aux rôles plus larges comme le président ou le secrétaire), pour que **l'une d'elles s'en charge elle-même** ; « Il faut n personnes » si plusieurs sont nécessaires. Elles la voient dans **« Mes tâches »** et sur leur accueil (bloc **🙋 À prendre**), avec une notification 🔔 ; la première qui clique **🙋 Je m'en charge** (dans la tâche ou sur sa carte) en devient responsable, et l'auteur de la tâche reçoit une notification 🙋. Une personne peut aussi répondre **🙅 Pas dispo** : la tâche quitte son accueil et ses notifications (elle reste dans « Mes tâches » tant qu'il y a une place, pour **changer d'avis** : « Je m'en charge quand même »), et l'auteur reçoit une notification 🙅 et voit dans la tâche qui a décliné ; quand plus personne n'a à répondre, la tâche porte **🙅 Personne de dispo** : à proposer à d'autres. Une fois les places prises, la tâche n'est plus proposée aux autres ; si on retire la personne des responsables, la place se libère. La tâche porte **🙋 À prendre** tant qu'il reste une place. Une tâche récurrente rouvre la proposition à chaque occurrence. Pas pour les remboursements et factures. Pas sur les remboursements et factures. **Onglet 💬 Messages** : toutes les discussions que la personne voit (ses tâches, celles qu'elle voit avec son rôle ou ses étiquettes, 👁 Pour info reçus), la plus récente en haut, avec le dernier message et son heure ; les non lues en gras avec leur nombre, total en pastille rouge sur l'onglet (sur « Plus » s'il n'est pas dans la barre du bas). Recherche (titre, texte, auteur), filtre « Non lues », **Nouvelle discussion** (choisir une tâche en cours) ; la discussion s'ouvre dans la même fenêtre, avec un bouton pour ouvrir la tâche. Enregistrer la tâche, la dupliquer ou passer à l'occurrence suivante d'une tâche répétée ne reprend pas la discussion. En version réelle : **migration 049** (seul le serveur écrit les commentaires : personne ne parle à la place d'un autre, et un enregistrement de la tâche ne les efface pas).
- **📝 Notes des séances** (sous la remarque, dès qu'un PV parle de la tâche) : la note prise sur ce point dans le PV de chaque séance (Comité › PV, « Note / décision sur ce point… »), mise en forme comprise, la séance la plus récente d'abord ; pour une tâche qui se répète, aussi les notes de ses occurrences précédentes (« occurrence précédente »). Qui a la page PV (`tab.minutes`) voit aussi les notes d'un PV pas encore validé ou rouvert pour correction (repère « PV en cours ») ; les autres voient seulement celles des PV validés (pendant une correction : celles de la dernière version validée). Lecture seule : les notes se modifient dans le PV.
- **🕘 Historique des changements**, sous la discussion (à déplier) : qui a changé quoi et quand, du plus récent au plus ancien : « Statut : À faire → En cours », « Délai : 12.11.2026 → 20.11.2026 », « Responsables : + Paul Exemple ; − Léa Exemple », titre, section, remarque, étapes de la checklist (ajoutées, cochées, retirées), documents, répétition, rattachements, étiquettes, état d'un paiement ; création, suppression et rétablissement. Les changements d'une même personne à moins de 10 minutes d'intervalle forment une seule ligne (une valeur revenue à son point de départ disparaît) ; 100 lignes par tâche au plus. Les lignes d'avant l'espace unique gardent leur texte (« Partagée avec … »). La discussion et les « ✓ Vu » n'y figurent pas (ils ont leur propre affichage). En version réelle : **migration 050** (le serveur note chaque changement, quel que soit l'appareil ; l'historique commence à l'application de 050) ; démo : noté dans ce navigateur.

## Délais calés sur un événement

**Nouvelle tâche : pour la prochaine séance.** Une nouvelle tâche (bouton « + Nouvelle tâche », bouton rond « + ») est réglée d'office sur la **prochaine séance de comité**, pas encore commencée (le soir d'une séance, après son heure de début : la suivante), **le jour même** : elle figure à son ordre du jour, et son délai suit la date de la séance si elle change. Créée en rédigeant un **PV** (« + Nouvelle tâche décidée »), elle va à la **séance suivante** (celle d'après la séance du PV, pas encore passée). Tout reste modifiable : la liste sous « Pour quand ? » propose les autres séances, les événements et « 📆 Date fixe », et le lien **« ou une date fixe »**, toujours affiché, passe directement à une date (celle de la séance, à changer ; « ou selon un événement / une séance » pour revenir) ; **« ✕ Aucun délai »** efface le délai (utile sur téléphone, où le calendrier ne propose pas d'effacer la date ; la tâche reste à l'ordre du jour de sa séance, à retirer dans « Rattachements » au besoin). Sans séance prévue dans l'Agenda, **aucun délai** ; une date cliquée dans l'Agenda, une tâche rattachée (« + Nouvelle tâche rattachée », qui reprend le délai de la tâche principale) et la page Tâches filtrée sur un événement gardent leur propre date.

Dans une tâche, **Pour quand ?** est une date ; le lien **📌 ou selon un événement / une séance** propose la liste des prochains événements, séances de comité et **étiquettes « événement » datées** (choisie, l'étiquette est mise sur la tâche), puis : un nombre libre de **jours, semaines ou mois**, **avant ou après** (ex. 10 jours avant, 6 semaines avant, 2 mois avant, 3 jours après ; 0 = le jour même). Par défaut, **le jour même** (le jour J) ; en changeant d'événement ou de séance, le décalage choisi est gardé. Les mois suivent le calendrier : « 1 mois avant » le 15.11 donne le 15.10.
Le délai **suit ensuite automatiquement** la date : si le tournoi est déplacé d'une semaine, toutes les tâches dont le délai est calé dessus bougent avec lui. Repère 📌 dans les listes (le survol indique la référence), filtre « 📌 Délai calé sur un événement / une séance » dans Tâches. Changer la date à la main détache le délai.
**Événement périodique** (🔁) : la liste propose sa prochaine occurrence ; un champ **Occurrence** permet d'en choisir une autre (les douze suivantes, avec jour et heures). Le délai suit cette occurrence (déplacée seule ou avec la série). Une tâche répétée rattachée à un événement périodique passe, une fois terminée, à **l'occurrence suivante** de l'événement.

## Tâches récurrentes

**Ajouter : 🔁 Répétition** dans une tâche : chaque semaine, mois, trimestre, semestre ou année, ou **à chaque comité** (repère 🔁, filtre « Tâches récurrentes »).
Quand la tâche passe à un statut de clôture (« Terminé »), la suivante est **créée automatiquement** avec le délai décalé, le statut « À faire » et la checklist remise à zéro. Elle est attribuée **au poste** (ex. Trésorier) : si le titulaire a changé entre-temps, elle va à son successeur. Une tâche rouverte puis refermée ne crée pas de doublon. Terminer une occurrence **bien avant son délai** (plus d'environ une demi-période : 6 mois pour une tâche annuelle, 15 jours pour une tâche mensuelle ; « à chaque séance » : délai après la prochaine séance) demande confirmation (« … est prévue pour le 10.10.2027. Elle se répète : la terminer maintenant crée déjà la suivante, pour le 10.10.2028. ») : l'occurrence suivante, à peine créée, n'est pas un doublon à cocher. Une tâche annuelle liée à une séance passe à la séance du même mois l'année suivante (voir « Séances qui reviennent chaque année »).

**🔁 À chaque comité** (ex. « Lire la correspondance », « Point des finances ») : la tâche est liée d'office à la prochaine séance prévue ; terminée, la suivante est liée à **la séance qui suit la sienne** (pas encore passée), et figure donc à son ordre du jour. Son délai garde le même écart avec la séance (2 jours avant reste 2 jours avant ; un délai lié « 1 semaine avant » est recalculé), un email programmé à date fixe aussi. Après la dernière séance prévue, la suivante va à la première séance de l'année prochaine à planifier (créée à ce moment-là, comme le propose l'Agenda) ; s'il n'y en a aucune, elle est créée sans séance ni délai. Le formulaire indique à l'avance la séance et le délai de la suivante.

## Séances qui reviennent chaque année

Une séance de comité **revient chaque année, le même mois** : le comité de mars 2026 a une suite en mars 2027.

- **Nom d'après le mois** : « Comité de mars 2027 », « Comité d’avril 2027 ». Le nom suit la date : une séance déplacée en avril (dans sa fiche, ou en la glissant dans l'Agenda) devient « … d’avril ». Un titre libre (« Assemblée des membres ») ne change pas. Une deuxième séance dans un mois qui a déjà la sienne s'appelle « Séance extraordinaire de … » et ne revient pas.
- **Fiche de la séance** : case **🔁 Revient chaque année** (cochée par défaut ; décochée = séance unique, marquée « une seule fois » dans la liste). Avertissement si le mois a déjà sa séance annuelle.
- **🔁 Séances de l’année prochaine** (Comité › Séances, pour qui gère les séances) : dès qu'une séance est passée, celle du même mois l'année suivante est proposée, **le même jour de la semaine au même rang** (2e jeudi d'avril → 2e jeudi d'avril ; un 5e mardi → dernier mardi), même heure et même lieu. On coche celles à ajouter (**📅 Ajouter les N séances**), ou **Ne revient plus** pour arrêter un mois.
- **Ajouter / supprimer un comité** : **+ Nouvelle séance** ajoute un mois au rythme annuel. **Supprimer** la seule séance d'un mois arrête ce mois (il n'est plus proposé ; le message le dit) ; pour changer de jour, on modifie plutôt la date.
- **Tâches annuelles rattachées à une séance** : quand une tâche « 🔁 Chaque année » rattachée au comité de mars est terminée, la suivante est rattachée au **comité de mars de l'année suivante** (créé au besoin, s'il n'existe pas encore et que le mois revient chaque année). Un délai calé sur la séance (« 2 semaines avant ») est gardé et recalculé sur la nouvelle date. Les autres répétitions (mois, trimestre…) ne reprennent pas la séance.
- **Anciens noms numérotés** (« Comité 4 », « Comité 1 (2027) ») : le panneau **✏️ Nommer les séances d’après leur mois** propose de les renommer en une fois (« Comité de septembre 2026 »), ou **Garder les noms actuels**. Les ordres du jour et PV déjà archivés gardent leur titre.

## Tâches rattachées et sous-tâches

Une tâche peut être **rattachée à une tâche principale** (un niveau) : par ex. « AG 13.03.2027 » avec « Reserver le lieu », « Organiser le repas », « Préparer le PowerPoint »… Chaque tâche rattachée est une tâche à part entière (responsables, délai, statut, remarque, documents, sondages, emails, répétition).

- Dans une tâche (**Ajouter : 🧩 Rattacher à…**) : champ **Tâche principale** (liste par section) ; une tâche rattachée affiche en haut « ↳ Tâche rattachée à … » (clic pour ouvrir la tâche principale).
- Dans une tâche principale (cadre **🧩 Rattachements**) : **Tâches rattachées** avec avancement (« 3/8 terminées »), statut, responsables et délai de chacune (clic pour l'ouvrir), **+ Nouvelle tâche rattachée** (section, sous-section et délai repris), **🧩 Rattacher une tâche existante**, ✕ pour détacher (la tâche reste), « Voir dans la liste ».
- Liste des tâches : repères « ↳ tâche principale » et « 🧩 3/8 tâches rattachées », filtre « Tâche principale » (la tâche et ses tâches rattachées), filtres « 🧩 Tâches principales » / « ↳ Tâches rattachées » ; export CSV : colonne « Tâche principale ».
- Ordre du jour : les tâches rattachées s'affichent sous leur tâche principale ; une tâche principale qui porte le nom de sa sous-section devient la ligne de la sous-section. Page PV : tâches rattachées en retrait sous leur tâche principale.
- Tâche récurrente : l'occurrence suivante d'une tâche rattachée l'est à l'occurrence suivante de sa tâche principale.
- Supprimer une tâche principale garde ses tâches rattachées (sans tâche principale).

**Repères** : 🔗 = lien web (documents « Lien ») ; 🧩 = tâche rattachée à un événement, une séance ou une autre tâche ; 📌 = délai calé sur un événement, une séance ou une étiquette datée ; 🙋 = tâche à prendre ; 🚫 = absent(e) à une séance.

Les **sous-tâches** restent une simple checklist (case à cocher + intitulé), cochables aussi pendant la séance dans Comité › PV.

## Emails programmés

Dans une tâche enregistrée, **Ajouter : 📧 Email** (puis **📧 Programmer un email** pour les suivants) : destinataires, **quand** (1 mois / 2 semaines / 1 semaine / 3 jours avant le délai, la veille, le jour même, 1 à 7 jours après pour une relance, ou date précise) et heure, objet et message avec champs automatiques ({tâche}, {délai}, {section}, {responsables}, {statut}, {remarque}, {lien}, {expéditeur}) et aperçu. Option « Ne pas envoyer si la tâche est déjà terminée ».

- **Destinataires** : les responsables de la tâche d'office (★), puis un **champ de recherche** (nom, prénom, poste, sans souci des accents ; ↑ ↓ et Entrée au clavier) : une **personne** du club qui a une fiche dans l'appli, ou une **étiquette** (🏷, événement ou groupe : l'email part à **tous ses membres**, lus au moment de l'envoyer, donc à jour des arrivées et des départs). Une **adresse email** tapée ou collée s'ajoute aussi (Entrée ou virgule). Chaque choix est une puce, ✕ pour la retirer ; une personne sans adresse, ou retirée du club, reste affichée avec ⚠. Le nombre d'adresses est indiqué ; une adresse présente deux fois ne reçoit l'email qu'une fois.
- Un email calé sur le délai **suit le délai** s'il change (y compris un délai lié à un événement).
- États : 🕓 programmé, 📨 à envoyer, ✅ envoyé (date), ⛔ annulé, ✔️ pas envoyé car tâche terminée ; actions Envoyer maintenant, Modifier, Annuler, Reprogrammer, Supprimer. Repère 📧 et filtre « Avec email programmé » dans Tâches.
- Tâche récurrente : les emails sont reconduits avec l'occurrence suivante (destinataires qui suivent le poste).

L'appli n'envoie pas l'email elle-même : à l'heure prévue, l'auteur reçoit une notification 🔔 (et de l'appareil si activée) ; **✉ Envoyer** ouvre l'email déjà rempli dans sa messagerie (toutes les adresses, une seule fois chacune), puis « Marquer comme envoyé ».

## Documents joints

Dans une tâche (**Ajouter : 📎 Document**) : **📎 Fichier** (PDF, Word, Excel, images… 10 Mo max), **📷 Photo** (appareil photo du téléphone, photo réduite automatiquement) et **🔗 Lien** (Google Drive, Dropbox, ClubDesk…). Clic sur un document pour l'ouvrir : un lien dans un nouvel onglet, un fichier dans la **visionneuse de l'appli** (la photo en grand, les pages d'un PDF, sinon « Pas d'aperçu » ; avec **Télécharger** et **Ouvrir à part**, qui agissent pendant le clic, le fichier étant déjà chargé ; « Fichier introuvable » s'il a été retiré, sans connexion ou sans droit de voir la tâche). Partout pareil : fiche, ordre du jour, PV, documents archivés, justificatifs des tickets. Pourquoi : sur téléphone, surtout dans l'appli installée, un fichier ouvert dans un nouvel onglet après son téléchargement est souvent bloqué ou reste vide, sans message. Aperçu des images ; repère 📎 dans les listes ; noms des documents sous la tâche dans l'ordre du jour.

Démo : le contenu des fichiers reste dans le navigateur de la personne qui les ajoute (les autres ne les voient pas) et est effacé par « Réinitialiser la démo ». Version réelle : sur le serveur (stockage privé `gsa-fichiers`), lisibles par qui voit la tâche ; les fichiers des tâches reprises des anciennes entités restent dans leur dossier et s'ouvrent de la même façon (migration 059).

## Sondages

Page **📊 Sondages** (rubrique à part, dans « Plus » sur téléphone sauf si on la met dans la barre du bas) (filtres À voter / En cours / Terminés), sondages liés à une tâche (**Ajouter : 📊 Sondage** dans la fiche de la tâche) ou rattachés à une section :

- **Oui / Non / Abstention**, **choix unique ou multiple**, **choix de dates** (type Doodle, avec tableau des disponibilités) ;
- réponse **« Autre »** en option (case à cocher à la création, pour les trois types ; « Autre proposition » pour les dates) : qui la choisit doit écrire sa réponse. Les textes s'affichent sous la ligne « Autre » (sans nom si le sondage est anonyme), dans le tableau des disponibilités et dans le résumé de l'ordre du jour et du PV. « Autre » n'est jamais désignée meilleure option ;
- votants choisis comme les responsables d’une tâche (une puce par votant, ✕ pour le retirer, liste « ＋ Ajouter… » ; raccourcis Comité / Tout le monde / Personne), réponses **nominatives ou anonymes**, date limite facultative, réponse modifiable tant que le sondage est ouvert ;
- **date et heure limite** facultatives, avec la case **« 🔒 Clôturer automatiquement à la date et à l’heure limite »** (cochée par défaut) : le sondage passe tout seul à « Clôturé » à l’heure dite (sans heure : à minuit, à la fin du jour), même page ouverte, et plus personne ne peut répondre. Décochée, la date est **indicative** (« réponses souhaitées d’ici le … ») et le sondage reste ouvert jusqu’à « Clôturer ». Une date et une heure déjà passées sont refusées (le sondage serait clôturé tout de suite). « Rouvrir » un sondage clôturé automatiquement retire la date limite. L’heure s’affiche partout : carte du sondage, accueil, notifications, agenda, message de partage, ordre du jour et PV ;
- résultats en barres, meilleure option ★, liste des personnes en attente ; clôturer / rouvrir / modifier / supprimer (créateur ou droit « Gérer tous les sondages ») ;
- notification 🔔 et encadré sur l'accueil quand un sondage attend ta réponse ; résultats résumés sous leur section dans l'**ordre du jour**.

Droits : « Créer des sondages » (Admin, Secrétaire, Comité par défaut) et « Gérer tous les sondages » (Admin, Secrétaire). Pour tester un vote à plusieurs, change d'utilisateur (bouton « Changer »).

## Envoyer une tâche ou un sondage par WhatsApp, email…

**Icône de partage** (trois points reliés, « Envoyer un lien ») en haut à droite de la fiche d'une tâche et de chaque sondage de la page Sondages. La fenêtre propose un court message, modifiable (« 📋 Tâche « … » · 📅 Pour le … · 👤 responsables » ou « 🙋 À prendre » ; « 📊 Sondage « … » · Réponds d'ici le … »), suivi du **lien** qui ouvre la tâche ou le sondage dans l'appli :

- **💬 WhatsApp** (appli ou WhatsApp Web, choix du contact ou du groupe), **Autre appli…** sur téléphone (Signal, SMS, Messenger… : la feuille de partage du téléphone), **✉ Email**, **📋 Copier le message** et **Copier le lien** seul ;
- le lien garde la **version** (`?reel` / `?demo` : pas d'écran de choix sur un appareil neuf), puis ouvre la tâche ou le sondage ; un lien d'avant D1, qui portait une entité (`?reel=<entité>`, `…&u=<entité>`), reste valable : l'entité est ignorée ;
- le lien **ne donne aucun accès** : il faut un compte, et voir la tâche avec son rôle (ou être votant du sondage). Sinon l'appli l'indique : « Tâche introuvable… » ou « Sondage introuvable… » ;
- le champ **{lien}** des emails programmés mène de la même façon à la tâche.

Démo : les données restent dans le navigateur, un lien n'ouvre donc l'élément que sur l'appareil où il a été créé.

## Ordre du jour

Page **📝 Ordre du jour** (rubrique Comité ; droit « Comité › Ordre du jour », donné au Président ; attribuable à d'autres rôles dans la console admin). Il prépare le document de la **prochaine séance** (Séances › « Séance à préparer » : seulement les séances à venir ; sans séance à venir, la dernière, marquée « passée »), présenté comme les ordres du jour Word du club, en **liste numérotée** (pas de tableau) :

- en-tête : **le nom du comité** (titre) et la date de la séance, début de séance, lieu, **convoqués** (avec initiales : les personnes dont un rôle donne la page « Séances » — admin, secrétaire, comité… —, ni les membres, ni les bénévoles, ni les personnes à qui une tâche est seulement confiée ; aussi pour « Je serai absent », les présences du PV, le rappel de la prochaine séance et les votants proposés d'un sondage), ligne **Excusés** à compléter ;
- **Ordre du jour** numéroté : **1. Section** (gras) › **a. Sous-section** › **■ point** (tâche avec initiales du responsable, délai, et selon le cas « ⚠ en retard », « pour le Comité 6 » (échéance à la date de la séance suivante ; avant elle, seulement la date), « après le Comité 6 » (voir la marge ci-dessous), « ✓ fait », statut, remarque) › **◦ détails** (checklist, documents joints, sondage lié) ;
- toujours **par section** : toutes les tâches de la section ensemble (retards, séance, séance suivante, terminées), sections sans point affichées seules ; sondages sous leur section ;
- cadre de notes et prochaine séance en pied de page ;
- **marge après la séance suivante** (Contenu, sous « Tâches à faire d'ici la séance suivante » : « et jusqu'à … après », de 3 jours à 1 mois ; défaut : non) : les tâches dont l'échéance tombe peu après la séance suivante sont reprises dès cette séance, marquées « après le Comité 6 », car la séance suivante serait trop tard pour en parler. Réglage **commun au club**, repris par le PV ;
- en option (Contenu › **📎 Joindre les fichiers liés en fin d'ordre du jour**), les **annexes** : voir « Fichiers liés en annexe » sous PV.

**Clic sur une tâche** du document (surlignée au survol) : sa fiche s'ouvre pour la modifier sur place ; l'ordre du jour se met à jour en la fermant. Pas dans une version modifiée à la main.

Réglages (mémorisés, panneau de gauche, toutes les parties fermées à l'ouverture) : **Séances** (à préparer, suivante), **Excusés**, **Contenu** (dans l'ordre du jour : parties du document ; sections : **niveau de détail** complet / sections et sous-sections / sections seulement, sections sans tâche, sections incluses ; tâches : statuts inclus, tri, ce qui est affiché pour chaque tâche ; annexes) et **Mise en page** (en-tête, orientation, taille du texte, **mise en forme**). Le PDF, l'archive et l'email portent le nom du comité et la date de la séance (« Comité central 29.10.26 »).

**Profils** (en tête des réglages) : un jeu de réglages enregistré sous un nom (« Comité ordinaire », « Assemblée générale »…), pour la prochaine fois : le **contenu** (parties, niveau de détail, sections et statuts inclus, tri, ce qui est affiché pour chaque tâche, annexes, « et jusqu'à … après »), l'**orientation**, la **taille du texte** et, si la case « Avec la mise en forme » est cochée, la **mise en forme** (🎨). **Un clic sur son nom** rétablit ces réglages (le profil en cours est coché ✓ et rappelé dans le titre « Profils · … », tant qu'aucun réglage n'a changé). les petites icônes à droite de son nom : **disquette** le remplace par les réglages actuels, **crayon** le renomme, **flèche** le remonte, **poubelle** le supprime (les réglages affichés ne changent pas). Les profils sont **personnels** : chacun enregistre les siens, les autres ne les voient pas (qui n'en a pas encore part des anciens profils communs du club, qui deviennent les siens dès qu'il en change un). Appliquer un profil change ses réglages à soi ; la mise en forme et « et jusqu'à … après », communes au club, ne changent qu'avec le droit « Comité › Ordre du jour ». Le choix de la séance, les excusés et les fichiers joints restent propres à chaque séance.
**Excusés** (panneau de gauche) : un clic sur un membre l'**excuse** (ou le retire) ; la ligne « Excusés » du document se remplit. Chacun peut aussi s'excuser lui-même dans **Comité › Séances** : **🚫 Je serai absent(e)** sur une séance à venir, avec un motif facultatif (« Je serai finalement présent(e) » pour annuler). Les excusés sont repris dans les présences du PV, et enregistrés avec lui à sa validation (même s'ils n'y ont pas été touchés).

**✏️ Modifier le texte** (droit « Comité › Ordre du jour ») : le document devient modifiable directement (corriger, ajouter ou supprimer des lignes), puis **Enregistrer**. Cette version, gardée dans la séance, est celle que tout le comité voit, imprime, archive, envoie et copie ; les excusés y restent à jour, mais plus les changements de tâches ni de mise en page. **🔄 Revenir à la version générée** l'abandonne.

**En-tête** : celui du club, le même pour tous les documents (voir « En-tête des documents » plus bas) ; la case « Afficher l'en-tête » (Mise en page) le masque sur l'ordre du jour. Les admins ont un lien **✏️ En-tête (console admin)** dans la mise en page.

**Mise en forme** (Mise en page, droit « Comité › Ordre du jour » ; aussi **🎨 Mise en forme** dans les options du PV) : **commune à l'ordre du jour et au PV du club**, pour tout le monde, appliquée tout de suite à l'aperçu :

- **police** (Arial, Calibri, Verdana, Georgia, Times New Roman), **interligne** (serré, normal, aéré), **marges** (étroites 8 mm, normales 12 mm, larges 20 mm, à l'écran et à l'impression) ;
- puis **chaque élément** au choix : titre (nom du comité), date, heure / lieu / convoqués, titres des parties, sections (1., 2.), sous-sections et points (a.), points (■), détails (◦), responsables / délais, remarques, notes et décisions du PV, prochaine séance, pied de page. Pour chacun : **taille** (70 à 200 %), **gras**, **italique**, **majuscules**, **centré** (titres) et **couleur** ; pour l'encadré « Prochaine séance », aussi la **couleur du fond** (bleu clair par défaut, teintes claires proposées, blanc = sans fond, ou toute autre couleur), le trait à sa gauche prenant la même teinte, foncée (gris pour un fond blanc) ;
- les tailles restent relatives à la « Taille du texte » de chacun (petite, normale, grande) ; agrandir un niveau ne grossit pas ceux qu'il contient ; « (modifié) » repère les éléments réglés, **Rétablir cet élément** / **Tout rétablir** ;
- un document **archivé garde la mise en forme du moment** (et ses marges à l'impression).

Actions : **PDF** (voir plus bas), **Imprimer**, **Archiver dans la séance** (copie figée consultable, réimprimable et exportable en PDF dans Comité › Séances), **Envoyer par email** aux membres du comité (ci-dessous), **Copier le texte** (même numérotation, prêt à coller dans Word, un email ou WhatsApp).

**Envoyer par email** : une fenêtre choisit séparément
- le **texte du mail** : les réglages affichés ou un **profil** (ex. « Comité ordinaire », version courte) ;
- le **PDF joint** : les réglages affichés, un **autre profil** (ex. version complète avec annexes et mise en forme) ou « Pas de PDF » ;
- le **lien du lieu**, quand la séance est placée sur une carte : une ligne « Itinéraire : … » sous « Lieu : … » ; sur téléphone, le lien ouvre l'**application de navigation** avec l'itinéraire jusqu'au lieu. Au choix : **Google Maps** (par défaut, aussi sur ordinateur), **Waze** (s'ouvre sur le lieu, « Y aller »), **Plans (Apple)**, **Voir sur la carte** (sans itinéraire) ou **Pas de lien**.

Le PDF est préparé tout de suite (nom et taille affichés, « Voir » pour le relire) ; « Aperçu du texte » montre le corps du mail. Puis :
- **Partager avec le PDF joint** (téléphone, tablette, et ordinateurs qui le permettent) : le mail ou WhatsApp s'ouvre avec le texte et le PDF en pièce jointe ;
- **Ouvrir dans ma messagerie** : le PDF est téléchargé, puis le mail s'ouvre adressé aux membres du comité, avec l'objet et le texte ; il reste à joindre le PDF (trombone ou glisser-déposer) — un lien « mailto » ne peut pas joindre de fichier. Certaines messageries coupaient le texte au premier « & » : dans les mails ouverts par l'appli (ordre du jour, PV, tâches), « & » est remplacé par « ＆ », de même aspect, et les liens du lieu n'en contiennent pas ;
- **Copier les adresses**.

Les profils choisis sont **mémorisés pour soi** (ce sont ses profils), le lien du lieu **pour le club** (droit « Comité › Ordre du jour ») ; un profil supprimé depuis revient aux réglages affichés. Un ordre du jour **modifié à la main** est envoyé tel quel (texte et PDF), sans profil.

## En-tête des documents

**Console admin › 📄 En-tête des documents** (admins) : **un seul en-tête**, repris par **tous les documents imprimés** : ordre du jour, PV et bon de paiement. Avec aperçu :

- image : le **logo du club**, une **image propre** (ex. l'en-tête du papier à lettres du club, réduite à 1400 px de large) ou aucune ; taille petite, moyenne, grande ou **toute la largeur** (bannière) ;
- texte libre sur plusieurs lignes (nom du club, adresse, site… ; la première ligne en gras), ou vide pour n'avoir que l'image ;
- disposition (image à gauche, image et texte opposés, centré, image à droite), couleur, trait sous l'en-tête ;
- « Revenir à l'en-tête par défaut », puis **Enregistrer**.

Par défaut : logo du club et « G.S. Ajoie – Comité ». Les ordres du jour et PV archivés reprennent l'image actuelle de l'en-tête (elle n'est pas recopiée dans chaque archive).

## PV (secrétaire)

Page **🖊️ PV** (rubrique Comité ; droit « Comité › PV », donné au Secrétaire et à l'Admin ; attribuable dans la console admin). Pour la séance choisie (par défaut celle du jour ou la prochaine ; la liste propose la dernière séance passée tant que son PV n'est pas validé, celles du jour et à venir, et les PV commencés ou en correction). Les autres séances passées, dont celles au PV validé, sont dans **Reprendre un ancien PV…** : le PV s'ouvre (validé : en lecture seule, « Corriger le PV » pour le rouvrir ; sans PV : à rédiger) :

- **Prise de notes** : reprend l'ordre du jour **dans le même ordre** (sections, sous-sections, tâches, sondages : même tri que l'ordre du jour de la personne connectée, tâche portant le nom de sa sous-section en tête, tâches rattachées et sondages sous leur tâche ; `ordreSection` et `blocsSection` dans `src/data/agenda.ts`, communs aux deux pages) avec une zone de notes pour chaque tâche (📝) et chaque sondage, une **à la fin de chaque section** (après ses points, aussi dans le PV, son PDF et son texte), plus « Divers » ; enregistrement automatique pendant la frappe.
- **Séance** : ▶ Démarrer (heure de début, état des tâches mémorisé) / ⏹ Terminer ; présences (Présent / Excusé, « Tous présents »), invités.
- **PV repris après la séance** (dès le lendemain, validé ou non, ou rouvert pour correction) : les points restent **tels qu'à la fin de la séance** (statut, délai, responsables, intitulé, checklist, et leur échéance : en retard, pour la séance, terminé…), repère 📌. Figés une fois, à la première ouverture du PV après la séance, d'après l'historique des tâches (migration 050 ; démo : historique du navigateur) : les changements notés après la fin du jour de la séance sont défaits, sauf ceux faits depuis le PV (son journal) ; gardés dans le PV (`MeetingMinutes.etats`, `src/data/etatsPv.ts`). Ensuite, ce qui est changé depuis le PV s'y reporte (et change la tâche) ; ce qui change ailleurs n'y apparaît plus. Historique illisible : les points tels qu'aujourd'hui, avec un avertissement, et nouvel essai à la prochaine ouverture.
- **Barre d'outils flottante** (pilule, icônes seules, survol : leur nom) pendant la prise de notes ; en titre, **la section à l'écran** (« Séance et présences » en haut de la page) : ↶ Annuler, ↷ Refaire, **︽ ︾ section précédente / suivante** (double chevron : défile jusqu'au point de l'ordre du jour d'avant ou d'après, sondages et Divers compris, son titre juste sous l'en-tête ; le survol dit lequel ; avant le premier point : le haut de la page ; au milieu d'un long point, « précédente » revient d'abord à son début ; la fin de page laisse de la place pour que le dernier point remonte lui aussi sous l'en-tête), **⌃ ⌄ point précédent / suivant** (simple chevron, entre les deux doubles : défile d'une tâche ou d'un sondage à l'autre, juste sous l'en-tête, le premier d'une section ou d'une sous-section avec son titre ; **après le dernier point d'une section, la note de la section**, le curseur placé dedans pour écrire tout de suite ; en repartant, la note est enregistrée ; sur un téléphone étroit, les boutons de la barre se resserrent pour qu'elle tienne à l'écran), **≡＋ nouvelle tâche décidée** rangée directement dans la section à l'écran (sections Sondages et Divers, ou section où l'on ne peut pas en créer : section à choisir dans la fenêtre), ▶ Démarrer / ⏹ Terminer la séance, **⏱ chrono** (dès le début de la séance : temps écoulé depuis l'heure de début, celle du champ « Début » si on l'a corrigée ; à la fin, la durée de la séance ; il reste affiché quand la barre est réduite), 💾 Enregistrer (enregistre la note en cours de frappe et l'envoie tout de suite au serveur ; pastille verte : tout est enregistré, orange : envoi en cours, rouge : hors ligne), et ⤡ pour la réduire à sa poignée. **2e ligne : mise en forme des notes** (s'applique au texte choisi dans la note où l'on écrit, aussi au doigt) : **A couleur** (palette : rouge, bleu, vert, orange, violet, gris, et « A » = couleur normale ; le trait sous le A montre la couleur du texte choisi), **B gras**, **I italique**, **U souligné**, **S barré** (bouton enfoncé : déjà appliqué ; re-clic pour retirer) ; au clavier Ctrl+B, Ctrl+I, Ctrl+U. Visible dans le PV, le PDF créé par l'appli, l'impression et les archives ; « Copier le texte » et l'email gardent le texte seul. Une note sans mise en forme reste du texte simple ; collé dans une note : le texte seul. On la **déplace** en tirant sa poignée ⠿ ou son titre (souris ou doigt ; flèches du clavier) ; **double-clic** sur l'un des deux : retour à sa place (en bas au centre, au-dessus du bouton + sur téléphone). Place et état réduit retenus sur l'appareil, en proportion de l'écran : elle garde sa place quand on tourne la tablette ou le téléphone, et reste à l'écran quand le clavier s'ouvre ; les messages s'affichent au-dessus d'elle.
- **↺ Remettre à zéro** (PV pas encore validé, commencé ou modifié, par exemple par erreur avant la séance) : après confirmation, notes, présences, invités, heures et début de séance sont effacés, et les tâches modifiées, créées ou supprimées depuis le PV reviennent comme avant (l'appli retient leur état d'avant la première modification faite depuis le PV ; une occurrence suivante créée en terminant une tâche répétée est retirée ; un champ changé depuis ailleurs est gardé). Les excuses annoncées restent, les options du PV aussi. **↶ Annuler** (en haut) défait la remise à zéro. Un PV validé se corrige avec « Corriger le PV » / « Annuler la correction ».
- **Mise à jour des tâches pendant la séance** : statut et délai directement sur la ligne ; **un appui sur le titre du point l'ouvre** (modification complète), **+ Nouvelle tâche décidée** (pour la séance suivante, le jour même, à son ordre du jour) ; les tâches modifiées sont surlignées avec le détail du changement (↻ statut / délai / responsable). Seules les modifications faites depuis la page PV figurent dans le PV (pas celles faites plus tard dans l'onglet Tâches).
- **📄 PV** : document « Procès-verbal » titré du **nom du comité** (PDF et archive « Comité central 29.10.26 ») avec heures, lieu, présents / excusés / absents / invités, points traités numérotés (notes, décisions, changements), nouvelles tâches décidées et prochaine séance.
- **Options du PV** (au-dessus du document, enregistrées dans la séance ; un nouveau PV reprend celles du PV précédent) : inclure tous les points de l'ordre du jour, responsables / délais / échéances, mises à jour des tâches (↻), **📎 joindre les fichiers liés en fin de PV** (avec le nombre de photos et de pages de PDF par page), taille du texte ; **🎨 Mise en forme** (police, marges, chaque élément : la même que pour l'ordre du jour, voir plus haut). Verrouillées une fois le PV validé (« Corriger le PV » pour les changer).
- **Pièces jointes des points** (PV et ordre du jour) : sous chaque tâche, ses documents sont nommés (« 📎 Devis.pdf, Site du fournisseur ») ; **un clic sur un fichier l'ouvre** dans la visionneuse de l'appli (photo, pages du PDF ; les autres : « Télécharger »), à l'écran comme dans un document archivé ou modifié à la main, aussi pour une tâche reprise d'une ancienne entité (fichier resté dans son dossier, lisible d'ici). Ordre du jour : Contenu › « Noms de ses documents » ; PV : Options du PV › **« 📎 Documents des points »** (cochée par défaut) ; la vue de saisie du PV les montre toujours sous le point.
- **Projection** (prise de notes diffusée sur un beamer ; bouton à côté de « Prise de notes | PV », retenu sur l'appareil, pas sur téléphone) : à droite des notes, **les pièces jointes du point en cours en grand**, pour que tous voient de quoi on parle. Point en cours : celui où l'on a placé le curseur en dernier (note, statut, délai…) tant qu'il est à l'écran, sinon celui juste sous l'en-tête ; les flèches de la pilule mènent au leur (un sondage rattaché à un point : les pièces jointes du point). La photo s'ajuste au panneau, les pages du PDF y défilent (sans faire défiler les notes) ; plusieurs pièces jointes : on choisit laquelle montrer (choix retenu en revenant au point) ; ⤢ ouvre la visionneuse, ⤓ télécharge ; un lien s'ouvre à part. Un point sans pièce jointe n'en montre aucune (jamais celle d'un autre point). Le panneau suit le point une fois le défilement posé (pas chaque point traversé) ; un clic dans le panneau ne change pas le point. La pilule se place au milieu des notes.
- **Fichiers liés en annexe** (PV et ordre du jour) : les documents des tâches du document sont numérotés (« Devis.pdf (annexe 1) » sous la tâche, ou « 📎 annexe 1, 2 » sur sa ligne si les documents ne sont pas nommés) et listés dans une partie **Annexes** (lien avec son adresse ; Word, Excel… « fichier à part »). Après le document, les **photos** et chaque **page des PDF** (30 au plus par PDF) sont reproduites, **1 (pleine page), 2 ou 4 par page imprimée** pour en réduire le nombre, réglé **à part pour les photos et pour les PDF** (« Photos par page », « Pages de PDF par page » ; PDF en pleine page par défaut, pour rester lisibles, tandis que les photos de tickets tiennent à 4 par page). Dans « Fichiers joints », chaque photo ou PDF a aussi son propre choix (« Comme les photos / les PDF », pleine page, 2 ou 4 par page), par exemple un plan en pleine page ou un ticket scanné en PDF à 4 par page, et chaque PDF de plusieurs pages un champ **Pages** (« 1-3, 5 », « 4- » jusqu'à la fin ; vide : toutes ; enregistré en quittant le champ ou avec Entrée) pour n'imprimer que celles utiles (la liste des annexes l'indique : « pages 1-3, 5 jointes »). Une page imprimée ne mélange pas deux mises en page, et les pages sont **regroupées par mise en page** (dans l'ordre où chacune apparaît) pour éviter les pages à moitié vides : tous les tickets à 4 par page ensemble, même séparés par un PDF dans l'ordre des annexes (chaque image garde son « Annexe n »). Les archives ne recopient pas ces images : elles sont relues à l'affichage (un fichier retiré depuis est signalé). L'email (lien `mailto:`) ne peut pas joindre de fichiers : il contient la liste des annexes. **Choix des fichiers joints** : sous l'option, la liste « Fichiers joints : n sur N » (miniature, nom, tâche) permet de décocher ceux à ne pas publier (« Tous » / « Aucun ») ; les annexes sont renumérotées. Un justificatif visé (facture, ticket) n'y figure qu'une fois, **en copie signée** : l'original, sans le sceau, reste dans la tâche. Le choix (fichiers joints, mise en page et pages de chacun) est commun au comité et propre à chaque séance : celui de l'ordre du jour est enregistré dans la séance ; le PV reprend ce choix tant qu'on ne change pas le sien, et le garde tel quel une fois validé.
- **En-tête** : celui du club, le même que l'ordre du jour et le bon de paiement (console admin › En-tête des documents).
- **📄 PDF**, **🖨 Imprimer**, **Copier le texte**, **Envoyer par email** au comité, **✅ Valider et archiver** : la secrétaire valide seule ; le PV validé est archivé dans la séance (Comité › Séances ; une fois la séance passée, sous « Séances passées ») et le comité est notifié 🔔.
- **📤 Dépôt du PV validé** (dans les options du PV, commun à tout le club) : l'adresse d'une page web où déposer le PV (dossier partagé du club, formulaire d'envoi… ; « www… » est complété en https, seules les adresses http(s) sont acceptées). « Valider et archiver » (et « Valider la version n ») ouvre alors cette page dans une nouvelle fenêtre et crée le PDF du PV validé (téléchargé, ou proposé au partage sur téléphone) : il reste à le glisser sur la page. Si le navigateur bloque la fenêtre, le message de validation donne le lien ; ensuite, le bouton **📤 Page de dépôt** la rouvre. La page ouverte n'a aucun accès à l'appli.
- **📄 PDF créé par l'appli** (ordre du jour, PV et documents archivés) : le PDF est fabriqué dans le navigateur, sans passer par l'impression, et téléchargé sous le nom du document (« Ordre du jour Comité central 29.10.26.pdf », « PV Comité central 29.10.26.pdf ») ; sur téléphone, il s'ouvre dans le partage (mail, WhatsApp…). **Les liens restent cliquables** : lieu de la séance placé sur une carte, documents « Lien » des tâches (sous la tâche et dans les Annexes), adresses web écrites dans les remarques, les notes du PV et les checklists (elles sont aussi cliquables à l'écran), liens contenus dans les PDF joints en annexe. Même rendu qu'à l'écran : mise en forme, police (polices libres embarquées : Liberation, Carlito, Gelasio, DejaVu ; voir `src/polices/LICENCES.md`), marges, orientation, numéros de page « 1 / 3 » et **pied de page** (« Document généré le… », « PV établi par… ») dans la marge du bas de chaque page, jamais sur une page à lui seul (à l'impression aussi, dans Chrome et Edge ; ailleurs, il reste à la fin du document), texte sélectionnable ; une ligne ou une image n'est jamais coupée entre deux pages, un titre (section, sous-section) ne reste pas seul en bas de page, un point n'est pas coupé ; **pas de page presque vide** : une longue section commence sur la page en cours et continue sur la suivante (à l'impression aussi), et un bloc gardé entier (« Prochaine séance », lignes de notes…) ne laisse jamais plus d'un tiers de page vide. Les pages des PDF joints sont reprises telles quelles (texte net), les photos en pleine qualité ; une page qui ne peut pas être reprise (page blanche sans contenu, PDF protégé…) est mise en image, sans faire échouer le document. En cas d'échec, l'appli propose « Imprimer › Enregistrer en PDF », avec le détail de l'erreur.
- **Correction après coup** : un PV validé passe en lecture seule ; **✏️ Corriger le PV** rouvre notes, présences et points (modifications de tâches comprises), **Annuler la correction** revient à la version validée. La nouvelle validation crée la **version 2** (« corrigée le … », email « PV corrigé »), l'ancienne version reste archivée et le comité est notifié.

## Remboursements et paiements (dans les tâches)

Pas d'onglet à part : les demandes sont des **tâches** (section des finances). Le **bouton flottant « + »** (en bas à droite, sur téléphone comme sur ordinateur, depuis n'importe quelle page) propose **✅ Nouvelle tâche** (la même fiche que partout) et :

- **🧾 Nouveau remboursement** : rembourser une personne qui a **avancé de l'argent** (photo de son ticket de caisse ; « À rembourser à » : soi-même, une personne du club ou un autre nom). Sous-section « Remboursements ». Pour un remboursement à soi-même, l'**IBAN enregistré** (Réglages › Mes données au club) est proposé ; si on n'en a pas encore, saisir un IBAN fait apparaître la case **« Enregistrer mon IBAN »** (message de confirmation à l'envoi).
- **💳 Nouveau paiement** : payer une **facture directement à qui l'a envoyée** (fournisseur, prestataire…) : photo ou PDF de la facture, « À payer à », IBAN s'il n'est pas sur la facture, **échéance** facultative (= délai de la tâche, visible dans l'agenda). Sous-section « Paiements ».

Le virement ne se fait pas dans l'appli : elle sert à **demander, viser et suivre**. Circuit : **justificatif → caisse → demande de visa → visa → virement**. Un clic sur la tâche ouvre la fenêtre de la demande (état, justificatifs, sceau, actions) au lieu du formulaire de tâche ; son statut suit le circuit (pas de changement direct, ni par glisser-déposer).

1. **Demande** : « + » › remboursement ou paiement (ou les raccourcis **Remboursement** / **Paiement** de l'icône) → photo prise directement avec l'appareil (📷 Photo) ou fichier existant (📎 Fichier, PDF compris), objet, montant, bénéficiaire, IBAN, remarque. La demande part à la caisse (« 📥 À traiter »).
2. **Caisse** (droit « Caisse », rôle Caissier ; les admins seulement si le club n'a pas de caissier, sinon un président qui vise ne voit pas les actions de la caisse) : contrôle le ticket puis **demande le visa** à un **membre du comité** (avec un message facultatif) ; les bénévoles ne sont pas proposés. Le demandeur n'est jamais proposé : **on ne vise pas sa propre demande**. La caisse peut aussi refuser, ou changer de signataire tant que le visa n'est pas donné.
3. **Visa** : la personne désignée ouvre le ticket, **glisse le sceau sur une zone libre de la photo** (taille réglable), peut adapter le texte, puis **signe au doigt, au stylet ou à la souris**. Le sceau « OK pour paiement · montant · date · signature · nom » est incrusté dans une copie du ticket (« ✔ Ticket visé », ajoutée aux justificatifs). Elle peut aussi refuser, avec un motif. Une fois le visa donné, la fenêtre se ferme et la demande revient à la caisse : la personne qui a visé n'a plus d'action possible (seule la caisse peut retirer un visa).

**Factures en PDF** (le format le plus courant) : elles s'affichent dans l'appli comme les photos, sans lecteur à part (utile sur téléphone et dans l'appli installée) : miniature de la première page dans le formulaire et la demande, **aperçu de toutes les pages** au clic, dans la visionneuse de l'appli (avec « Télécharger » et « Ouvrir à part »). Au visa, la page s'affiche pour y placer le sceau ; pour un PDF de plusieurs pages, « Page du sceau » choisit la page. Le sceau est **posé dans le PDF lui-même** : la « facture visée » reste un PDF (texte net, toutes ses pages), téléchargé en `.pdf`. Pages en paysage ou tournées comprises. Si le sceau ne peut pas être posé dans le PDF (PDF protégé…), la facture visée est l'image de la page, en JPEG. Le bon de paiement imprime la première page du PDF.

**Visa direct d'une facture** : la personne qui envoie une facture et qui a le **droit de signature** (« peut viser », ou admin, ex. le président) la vise elle-même avant l'envoi (case « ✍️ Je la vise moi-même », cochée d'office) : elle place le sceau et signe, et la facture arrive à la caisse **« Visé – virement à faire »**, sans aller-retour pour la signature. Rien n'est envoyé si elle annule le visa. Une facture envoyée sans visa peut encore être visée par elle (« Viser moi-même », tant que la caisse n'a pas demandé de visa). Jamais pour un remboursement, ni pour une facture à son propre nom, ni par la caisse elle-même (une autre personne fait le virement). Le bon et la demande indiquent « visa direct (droit de signature) ». Le serveur applique les mêmes règles (migration 024).
**Visa sécurisé** (pour que personne ne vise à la place d'un autre) :
- **Mot de passe redemandé** : au moment de signer, la personne qui vise confirme son mot de passe (version réelle). Un téléphone resté ouvert ou une session volée ne suffit donc pas ; le serveur refuse tout visa sans mot de passe saisi dans les 10 minutes (migration 043).
- **N° de visa** : chaque visa reçoit un numéro unique tiré au hasard (ex. `K7PM-2XQD`), **imprimé en bas du sceau** (document visé, bon de paiement) et affiché sur la demande. Le serveur refuse un visa sans numéro, avec un numéro déjà pris ou antidaté (date du visa = heure du serveur, à quelques minutes près).
- **Signature marquée** : la signature n'est enregistrée qu'avec le n° de visa et la date en filigrane ; copiée depuis une demande ou un document, elle reste liée à ce visa. Elle n'est jamais mémorisée d'un visa à l'autre : on signe à chaque fois.
- **Vérifier un visa** (sous Filtres › « 💰 Paiements et remboursements ») : le n° lu sur un document visé retrouve la demande, dans tout le club, anciennes entités comprises (espace, titre, montant, bénéficiaire, qui a visé et quand, état ; jamais l'IBAN). Le document doit montrer le même montant, le même bénéficiaire, la même date et le même nom : sinon, il a été modifié ou le sceau copié. Un visa retiré ou une demande supprimée donnent « n° inconnu ». En version réelle, réservé aux membres du club (fonction `gsa_verifier_visa`, migration 043).
- Les visas donnés avant la migration 043 restent valables tels quels, sans numéro.

4. **Paiement** : la caisse **télécharge le document fini** (« Télécharger : ticket visé / facture visée » : la photo ou le PDF avec le sceau signé), fait le virement dans son e-banking puis appuie sur **✅ Virement fait (OK)** → « Payé ».

**Supprimer une demande** : tant qu'elle est reçue ou refusée, la personne qui l'a faite ou la caisse (« Supprimer »). Une fois le visa demandé, visée ou payée, **la caisse seule** (« Supprimer… », sous les boutons), pour une demande de test ou une erreur : la confirmation rappelle son état ; la demande disparaît avec ses justificatifs (et la copie visée), et la suppression reste notée dans le journal. Le serveur applique la même règle (migration 009).

**Une seule caisse** : celle du club, tenue par les personnes qui ont le rôle **Caissier** (à donner sur la fiche de la personne, « Personnes du club »). Sans caissier désigné, aucune demande ne peut être envoyée (le formulaire le dit).


**Sceau modifiable** : la caisse règle le modèle (« Sceau », affiché quand la liste des tâches est filtrée sur les paiements : Filtres › « 💰 Paiements et remboursements ») : en-tête (ex. « G.S. Ajoie – Caisse »), texte (« OK pour paiement », « Bon pour paiement »…), couleur et **transparence** : du fond (de blanc opaque à entièrement transparent, pour laisser voir le document sous le sceau) et du texte et du cadre, avec un aperçu sur un faux document. La personne qui vise peut encore ajuster la transparence du fond selon la photo. Le droit « peut viser » (console admin, groupe Gestion) place des personnes en tête de la liste proposée à la caisse ; par défaut les admins.

**Accès** : seules la caisse, la personne qui a fait la demande et celle qui doit la viser (tant que le visa est demandé) peuvent ouvrir la demande, admins compris ; la personne qui a visé et les admins la voient dans la liste avec un 🔒, sans pouvoir l'ouvrir ; les autres membres ne la voient pas du tout, même avec « Voir toutes les tâches » (en version réelle, le serveur ne la leur envoie pas, ni ses justificatifs : migration 029). La tâche passe de la caisse à la personne qui vise, revient à la caisse puis se clôt une fois payée ; la liste affiche le montant et l'étape (« CHF 42,50 · ✍️ Visa demandé »). « Mes tâches » montre aussi les demandes qu'on a envoyées, pour en suivre l'état. Filtre « Tâches et paiements » : paiements et remboursements, remboursements seuls ou factures seules (avec le total). Notifications : demande à traiter et virement à faire (caisse), visa demandé (signataire), « visé / remboursé / payé / refusé » (demandeur) ; elles ouvrent directement la demande. **🖨 Bon de paiement** imprime la demande visée : l'en-tête du club, le justificatif d'origine (sans la copie visée) et, en bas, le sceau signé (seule la fenêtre est imprimée). **En-tête du bon** : celui du club, le même que l'ordre du jour et le PV (console admin › En-tête des documents). Les anciens liens `#/paiements` mènent aux tâches. En version réelle, le serveur applique les mêmes règles, admins compris (voir SUPABASE_SETUP.md, migrations 009 et 010).

## Notifications

Cloche 🔔 dans l'en-tête (ordinateur et mobile), avec pastille du nombre de notifications non lues :

- 🆕 une tâche t'est attribuée par quelqu'un d'autre ;
- 📧 un email que tu as programmé arrive à son heure d'envoi (message à l'écran si l'appli est ouverte) ;
- ✏️ une de tes tâches est modifiée par quelqu'un d'autre (statut, délai, contenu) ; 🔁 tâche récurrente reconduite ;
- 💬 quelqu'un commente une tâche dont tu t'occupes, que tu as créée ou que tu as déjà commentée (voir « Discussion » dans la fiche d'une tâche) ;
- ⏰ échéance proche (le jour même à 14 jours avant, réglable) ;
- ⚠️ résumé quotidien de tes tâches en retard ;
- 📅 le lundi, **résumé de ta semaine** : tâches à faire d'ici dimanche (en retard comprises, les plus proches citées), séances de comité, événements et sondages qui attendent ton vote ; un clic ouvre « Cette semaine » dans Tâches (filtre Délai) ;
- 🗓️ prochaine séance de comité (et « ordre du jour disponible » s'il a été archivé).

Un clic ouvre directement la tâche (ou la liste filtrée / Comité › Séances). Réglages → Notifications, en trois groupes : **Tâches** (confiée, pour info, proposée ; modifiée ou reconduite ; échéance ; retard ; email programmé), **Messagerie** (💬 messages, une case à part) et **Agenda et sondages** (résumé de la semaine, sondage, séance) ; délais de prévenance, et **notifications de l'appareil** (téléphone / ordinateur, après autorisation) avec un bouton de test.

Démo : sans serveur, les notifications sont calculées dans le navigateur et celles de l'appareil ne partent qu'à l'ouverture de l'appli.

**Version réelle : sur le téléphone, même l'appli fermée.** Réglages › Notifications › **« 📲 Recevoir ces notifications sur cet appareil, même l'appli fermée »** (à cocher sur chaque appareil : téléphone, ordinateur ; le navigateur demande l'autorisation), puis « Envoyer une notification d'essai ». Le serveur envoie ce qui est nouveau dans ta cloche 🔔 (selon les choix cochés au-dessus) **tout de suite** pour une notification (message, ajout à une discussion, point confié…, migration 064 : un seul envoi à la fois, jamais deux fois la même), et toutes les 5 minutes pour le reste (échéances, retards, résumé de la semaine) ; ce que tu as déjà vu dans l'appli n'est pas envoyé, et au-delà de trois nouveautés d'un coup, un seul message les résume. Rien entre 22 h et 7 h : ce qui arrive la nuit part le matin. Un clic sur la notification ouvre l'appli sur la tâche (une notification 💬 ou 📣 ouvre sa discussion dans « Messages » : la croix ramène aux discussions, l'icône de la tâche ouvre sa fiche). Sur **iPhone et iPad**, installe d'abord l'appli sur l'écran d'accueil (iOS 16.4 ou plus récent) et active-les depuis l'appli installée. Serveur : migration 047 et fonction `gsa-push` (voir SUPABASE_SETUP.md).

## Sauvegarde des données

**Console admin › Sauvegarde** :

- **⬇ Télécharger la sauvegarde du club** (super-admins du club ; dans la démo : admins) : un seul fichier `.json` avec **tout le club** (tâches, séances, PV, sondages, emails, étiquettes, personnes, rôles, réglages et fichiers joints) et **« Personnes du club »** (sans IBAN) ; en version réelle, aussi les anciennes entités, archivées telles qu'elles étaient avant leur reprise dans le club. Version réelle : migration 057 (`gsa_sauvegarde_club`).
- **⬆ Restaurer depuis une sauvegarde…** (admins) : remet **l'espace du club**, depuis la sauvegarde du club (retrouvé par son identifiant, sinon par son nom) ou depuis une ancienne sauvegarde (format mis à niveau automatiquement). Les fichiers joints du fichier sont remis aussi.

Sert aussi à passer d'un appareil à l'autre et à reprendre les données saisies dans la démo dans la version définitive. Ne pas déposer ce fichier dans le dépôt GitHub (public).

**Copies automatiques** (version réelle, migration 036) : chaque nuit, le serveur garde une copie complète des données, si quelque chose a changé depuis la veille, pendant **30 jours** (la plus récente est toujours gardée). Les admins les retrouvent dans Console admin › Sauvegarde › **Copies automatiques** : ⬇ télécharger une copie (même format qu'une sauvegarde), **↩ Restaurer** (l'état actuel est d'abord copié : la restauration peut être annulée depuis la même liste), **📸 Copier maintenant**. Les fichiers joints ne sont pas dans ces copies : ils restent rangés sur le serveur et la restauration n'y touche pas. Restaurer un fichier de sauvegarde fait aussi une copie de l'état actuel juste avant.

## Mobile et installation (PWA)

Sous 768 px : barre de navigation en bas, tâches en cartes avec changement de statut d'un tap, bouton **+** pour ajouter une tâche, un remboursement ou un paiement.

L'application peut s'installer comme une vraie appli (icône, fenêtre dédiée, fonctionne hors connexion) via le bouton **📲 Installer l'application** (en-tête, menu « Plus » sur mobile, ou Réglages → Application) :

| Appareil | Comment |
|---|---|
| Ordinateur – Chrome / Edge | Bouton « Installer l'application » ou icône d'installation dans la barre d'adresse |
| Mac – Safari | Fichier › Ajouter au Dock |
| Android – Chrome | Bouton « Installer l'application » ou menu ⋮ › Installer l'application |
| iPhone / iPad – Safari | Bouton Partager › Sur l'écran d'accueil |

**Ouverture rapide** : au lancement, l'appli ne charge que l'accueil et la liste des tâches (environ 270 Ko compressés au lieu de 410). Les autres pages (séances, ordre du jour, PV, sondages, agenda, membres, réglages, console admin, aide) et la fiche d'une tâche se chargent ensuite en arrière-plan, une à une, quand le navigateur a le temps : elles sont prêtes au premier clic et gardées pour le hors-ligne. Une page encore en route affiche « Chargement de la page… » un instant. Hors connexion juste après une mise à jour, une page pas encore chargée le dit : se reconnecter puis recharger.

Un appui long (ou clic droit) sur l'icône installée propose les raccourcis **Nouvelle tâche**, **Remboursement**, **Paiement** (ouvrent directement le formulaire) et **Mes tâches**. Sur Android, Chrome ajoute « Paramètres des sites » et le lanceur n'affiche que 4 raccourcis : « Mes tâches », placé en dernier, n'y apparaît pas. Une appli déjà installée prend les nouveaux raccourcis à sa prochaine mise à jour (Android la fait de lui-même, en général dans la journée où l'appli est ouverte) ou en la réinstallant.

**Nom et icône de l'appli** : par défaut « Tâches GSA » et le **logo du G.S. Ajoie** (écran d'accueil, raccourcis, notifications ; les raccourcis ont chacun leur icône). Les admins les changent dans **Console admin › Apparence** (version réelle), section « Nom et icône de l'appli installée » :
- **Nom** : jusqu'à 30 caractères (sous l'icône, il est coupé au-delà d'une douzaine) ; repris dans l'en-tête de l'appli, l'onglet du navigateur, l'écran de connexion, les notifications, les emails d'accès et le pied des documents imprimés. « Reprendre « Tâches GSA » » revient au nom d'origine.
- **Icône** : mettre le logo du club (plus haut), puis **« Utiliser le logo du club comme icône »** (aperçu de l'icône et des raccourcis, qui prennent la couleur de l'appli du club). « Revenir à l'icône d'origine » remet le logo du G.S. Ajoie. Après un changement du logo ou de la couleur, le panneau propose de mettre l'icône à jour.

L'appli dépose le nom et les images sur le serveur (migration 017) ; le site les publie **dans l'heure** (vérification automatique toutes les heures, workflow « Nom et icône de l'appli » ; « Run workflow » dans l'onglet Actions de GitHub pour le faire tout de suite). Une appli **déjà installée** se met à jour d'elle-même après un moment (Android) ; sinon la supprimer puis la réinstaller (ou la rajouter à l'écran d'accueil sur iPhone / iPad).

> GitHub désactive les tâches planifiées d'un dépôt public resté 60 jours sans modification : si le nom ou l'icône n'est toujours pas en ligne après quelques heures, lancer « Nom et icône de l'appli › Run workflow » dans l'onglet Actions (et réactiver le workflow si GitHub le propose).

**Barre du téléphone** (appli installée sur Android) : Chrome colore la barre des touches du téléphone (◁ ○ □) avec la couleur du manifeste (`theme_color`) : blanc, comme la barre du bas de l'appli. Un changement arrive sur les téléphones quand Chrome relit le manifeste (au plus tard un jour après une ouverture de l'appli).

L'installation n'est possible que depuis une adresse **https://** : utilise la version en ligne ci-dessus (ou `npm run build && npm run preview` puis http://localhost:4173 sur l'ordinateur qui fait tourner l'appli).

## Publication (GitHub Pages)

Le workflow `.github/workflows/deploy-pages.yml` construit et publie l'application à chaque push sur la branche principale ; on peut aussi le relancer à la main (onglet **Actions › Publication GitHub Pages › Run workflow**). L'application installée se met à jour d'elle-même au lancement suivant. Les fichiers des 20 versions précédentes (14 jours au plus) restent publiés (`scripts/anciens-assets.mjs`, liste dans `versions-assets.json`) : une appli restée ouverte pendant une publication, sur téléphone surtout, crée encore ses PDF et affiche la carte. Si un fichier manque malgré tout, l'appli demande de recharger la page.

**Contrôles avant publication.** Le workflow vérifie d'abord le code (`npm run lint`, types à la construction), puis lance les tests automatiques de la démo (`tests/`, Playwright) sur la version construite : toutes les pages s'ouvrent sans erreur, création d'une tâche (checklist, répétition, à prendre, pour info), Annuler / Refaire, données gardées après rechargement, recherche globale, étiquettes, un seul espace (plus aucun texte sur les entités dans l'aide), affichage sur téléphone. Si un contrôle échoue, rien n'est publié : la version en ligne reste la précédente, et les captures du test en échec sont jointes à l'exécution (onglet **Actions**, « resultats-tests »). En local : `npm run build && npm test`.

Réglages GitHub nécessaires (une seule fois) :
1. **Settings › General › Danger Zone › Change visibility › Public** (Pages n'est pas disponible sur un dépôt privé avec un compte gratuit).
2. **Settings › Pages › Build and deployment › Source : GitHub Actions**.

## Version réelle (Supabase)

La version réelle utilise la même appli, à la même adresse : au premier passage, un écran d'accueil propose **Version réelle** (membres du comité, email + mot de passe, données partagées en direct) ou **Démo** (données fictives dans le navigateur, pour faire essayer). Le choix est retenu sur l'appareil. On change depuis la page de connexion (« Essayer la démo », pratique pour tester une mise à jour sans toucher aux données du club ; « Version réelle » dans la démo) ou les Réglages de la démo. Hors de ces boutons, la version réelle n'affiche aucun texte sur la démo. Le message d'accès envoyé à une personne (mot de passe provisoire) contient le lien `?reel`, qui ouvre directement la version réelle.

Liens directs : https://lionelbonati-lab.github.io/Taches_GSA/?demo (à envoyer aux testeurs) et https://lionelbonati-lab.github.io/Taches_GSA/?reel (membres du comité).

- **Synchronisation** : le badge en haut à gauche indique ☁ À jour, ⏳ Envoi… ou ⚠ Hors ligne (avec le nombre de modifications en attente, envoyées au retour du réseau). Sur téléphone et écran moyen, ☁ et ⏳ en icône seule (le texte au survol) ; « Hors ligne » reste écrit.

- **Données** : chaque élément (tâche, séance, responsable, entrée du journal…) est une ligne de la table `gsa_items` ; seuls les éléments modifiés sont envoyés, avec une file d'attente en cas de coupure, et les modifications des autres membres arrivent en direct (`src/data/cloud.ts`).
- **Accès** : « Personnes du club » › clic sur la personne › **Donner l'accès** crée son compte avec un mot de passe provisoire (à lui transmettre). Une seule personne = un seul compte (`gsa_club_comptes`, migration 056) ; son accès suit sa fiche dans l'appli : active, elle ouvre l'espace du club ; désactivée (« Retirer du club »), plus rien. Un compte sans fiche active dans l'appli : ses tâches confiées seulement.
- **Mot de passe provisoire** : il doit être changé à la première connexion. C'est appliqué par le serveur : tant qu'il n'est pas changé, le compte ne lit ni n'écrit aucune donnée, même en passant à côté de l'appli.
- **Mot de passe oublié** (page de connexion) :
  - **📧 Recevoir un lien par email** : lien valable 1 heure, une seule fois, qui ouvre l'appli sur le choix d'un nouveau mot de passe (une fois le serveur d'emails réglé, voir [SUPABASE_SETUP.md](SUPABASE_SETUP.md#emails-du-mot-de-passe-oublié)) ;
  - **✉ Demander aux admins du club** : la demande arrive (cloche 🔑, menu du compte › « Mots de passe oubliés (n) ») chez les admins ; **une seule validation suffit** : l'admin vérifie que la demande vient bien d'elle et lui transmet le mot de passe provisoire. Le compte d'un admin se valide par un autre admin ou un super-admin. Même réponse que l'adresse existe ou non ; 3 demandes par jour au plus.
- **Super-admin** (au départ : le propriétaire de l'espace du club) : menu du compte › **🔐 Comptes du club** : tous les comptes et leurs espaces sur le serveur (celui du club ; les anciennes entités, archivées, en gris), nouveau mot de passe provisoire, **blocage / déblocage** d'un compte, **fusion** de deux comptes d'une même personne (espaces, fiches, tickets et propositions passent au compte gardé ; l'autre est supprimé). Un super-admin sans fiche n'a que cette page.
- **Mise en route** : à la première connexion du président, reprise d'une sauvegarde de la démo (Console admin › Sauvegarde ; la sauvegarde du club est acceptée : l'espace du club y est repris) ou base vide.
- **Fichiers joints** : stockage privé du serveur, dossier de l'espace du club ; un fichier joint à une tâche ne se lit que si l'on peut voir cette tâche. Ceux des tâches reprises des anciennes entités restent dans leur dossier, avec la même règle (`gsa_fichier_repris`, migration 059).
- **Droits appliqués par le serveur** : chacun ne reçoit que les tâches qu'il peut voir (voir « Rôles et permissions » : externes, bénévoles, tickets), avec leurs emails programmés ; les notifications qu'il reçoit ou envoie ; le journal seulement avec l'accès à la console admin. Une tâche qu'on confie à quelqu'un d'autre sans avoir « Voir toutes les tâches » quitte sa liste (sauf si on l'a créée).
- **Anciennes entités** : chaque ancien sous-comité, groupe ou équipe a été repris dans le club le 03.11.2026 (migrations 059 et 060, `PLAN_APPLI_SIMPLE.md`) : une étiquette, avec ses tâches et ses personnes. Les entités restent sur le serveur, **archivées**, avec leurs données d'avant la reprise (rien n'est effacé) ; l'appli ne les ouvre plus. L'espace du club est l'ancien comité central.

Détails techniques (tables, règles d'accès, fonction serveur) : [SUPABASE_SETUP.md](SUPABASE_SETUP.md).
